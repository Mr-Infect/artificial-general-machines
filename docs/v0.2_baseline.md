# v0.2 baseline: frozen v0.1 state

This document records the v0.1 laboratory exactly as it was before any v0.2 change, so that every later result can be compared against a fixed, reproduced reference. Git tag: `agm-v0.1-freeze`.

## Current architecture (v0.1)

| layer | module | role |
|---|---|---|
| IR | `architecture/ir.py`, `architecture/validate.py` | versioned Architecture IR (v0.1), schema/registry/environment validation, canonical hash, diff distance, derived versions with lineage |
| registry | `core/registry.py`, `configs/capabilities.yaml` | 27 capabilities: 4 simulated models, 5 reasoning types, 4 memory types, 4 verification types, 5 tools, 5 perception components |
| compiler | `compiler/compile.py` | IR → `CompiledSpec` (pipeline, cost profiles, limits, static estimates) |
| sandbox | `sandbox/runner.py`, `sandbox/Dockerfile`, `runtime/executor.py` | stdlib interpreter of compiled specs inside a locked-down container; process executor for tests |
| environments | `environments/profile.py`, `environments/synthetic.py`, `environments/scoring.py` | EnvironmentProfile + 10 event types; domains `network` and `scientific`; F1/specificity scoring |
| agents | `baselines/{fixed,adaptive,search,self_evolving,agm}.py` | B0–B4; B4 is the bounded AGM prototype |
| economics | `runtime/economics.py` | ADAPT / PARTIAL_ADAPT / DO_NOT_ADAPT / TERMINATE with recorded inputs |
| memory | `memory/structural.py` | architecture patterns keyed by environment signature + task characteristics (`environment → architecture`) |
| telemetry | `telemetry/telemetry.py` | JSONL + SQLite; the only channel agents observe |
| persistence | `core/db.py` | SQLite tables: experiments, architectures, executions, evaluations, metrics, environment_events, adaptation_decisions, architectural_patterns, telemetry |
| runner / reports | `experiments/run.py`, `experiments/report.py`, `experiments/manifest.py` | manifests, replay, per-experiment and suite reports (bootstrap CIs, Pareto, transfer deltas) |
| API | `core/api.py` | read-only FastAPI inspection |
| tests | `tests/` | 16 tests, all passing |

## Known limitations of v0.1

- Structural memory stores `environment → architecture` patterns; it has no notion of *why* an architecture worked (no principle abstraction).
- Only two domains, both anomaly-flagging over a numeric stream; they share the same perception components, so "structurally different" is weak.
- The AGM's synthesis is heuristic template generation; the search space is the registry product, and novelty is a single distance number relative to the agent's prior library.
- Adaptation economics estimates only expected quality improvement vs. search/validation cost; no risk term, no post-hoc decision-error accounting.
- Registry "models" are simulated compute profiles; no LLM proposer exists.
- 3 seeds per domain; CIs are wide.
- No event stream, no live observability, no visual replay.

**Conclusion of v0.1:** the AGM prototype has NOT demonstrated cross-domain architectural transfer. Memory from Domain A made Domain B quality slightly worse and required one more architecture evaluation on average. This result is the starting point for v0.2, not a problem to be engineered away.
