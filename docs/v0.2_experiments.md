# v0.2 experiment program

Driver: `scripts/run_v02_experiments.py --seeds 30 --workers 4 --executor process`.
Analysis: `python -m experiments.analysis` → `results/v02/analysis/analysis.md`.

Every generated manifest is stored under `results/v02/manifests/` and can be re-run alone with
`python -m experiments.run <manifest>`. Memory files are per seed under `results/v02/memory/`, so
every comparison within an experiment is paired by seed and isolated from other seeds.

## Conditions shared by all runs

2000 records, noise 0.1, 5 steps of 10 logical seconds, validation slice 20 %, environment 512 MB /
1 CPU / network on at t=0, events: memory → 80 MB at t=10, network loss and removal of
`large_reasoner`, `search`, `lookahead_planner` at t=20, latency budget → 800 ms at t=30, priority
→ 3 at t=40. Budget 0.25 simulated USD, 120 s deadline, 30 s step timeout.

**Target quality** is computed per dataset by a lab-side oracle: 0.9 × the best validation-slice
quality over the enumerated wide architecture space (`enumerate_wide_space`; process executor; not an
agent). It is recorded in `provenance.json` under `objective` together with the whole space's
validation results. "Evaluations-to-target" is the cumulative number of candidate evaluations an
agent had made when one first reached the target on validation.

## Agents

| name | what |
|---|---|
| fixed, adaptive, search, self_evolving | v0.1 baselines unchanged |
| agm_v1_* | AGM v0.1 (architecture-pattern memory) |
| v2_cold / agm_v2_cold | AGM v0.2, no memory |
| agm_v2_explore / agm_v2_src | AGM v0.2 in exploration mode (up to 8 evaluations per step even after the target is met) — the experience-gathering phase that writes memory |
| v2_from_S | AGM v0.2 full memory from source domain S only |
| v2_warm_full / architecture / principle / task | memory-mode ablation with merged memory from the two other domains |
| v2_always_adapt / v2_never_adapt | economics ablation, no memory |
| v1_warm_architecture | AGM v0.1 reading the merged patterns |

## Experiments

| # | question | runs | analysis |
|---|---|---|---|
| 1 | Was the v0.1 negative transfer result noise or persistent? | `v02_exp1_A` → `v02_exp1_B` (A memory read in B) | paired memory − cold for v0.1 and v0.2 |
| 2 | Does memory from one domain reduce adaptation/search cost in another? | `v02_exp2_src_{A,B,C}` → `v02_exp2_tgt_{A,B,C}` | transfer matrix, primary metric Δ adaptation cost, secondary Δ evaluations, Δ evaluations-to-target, Δ quality, Δ failures, distance, principle reuse |
| 3 | Do principles matter? | same target runs | v2_warm_principle vs v2_warm_architecture vs cold |
| 4 | Which memory kind carries the effect? | same | none / task / architecture / principle / full |
| 5 | Does the machine know when not to adapt? | same | economic vs always vs never; wasted evaluations; decision error |
| 6 | Are solutions nearby mutations or new regions? | exp1 + exp2 | distance to initial, novelty levels, reached vs not |
| 7 | Cold vs warm | same target runs | v2_cold vs v2_warm_full: evaluations-to-target, time-to-target, cost, quality, failures |
| 8 | Held-out conditions | `v02_exp8_heldout_{A,B,C}` (cpu 0.5, 100 MB from t=0, noise 0.3, verification cost ×8) | cold vs warm with standard-condition memory |
| 9 | LLM proposer | not run in v0.2 (see report) | — |

## Executor note

The 30-seed program uses the process executor for all agents (identical execution environment for
every compared agent; the runner is fixed code, no generated code exists). The v0.1 freeze runs and
the example manifests use Docker. `provenance.json` records the executor of every run.
