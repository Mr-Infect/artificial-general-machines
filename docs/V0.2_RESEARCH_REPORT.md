# AGM v0.2 Research Report

**Question.** Is there measurable evidence that AGM is learning transferable principles of computational organization, rather than merely searching, mutating, or memorizing architectures?

**Answer: no.** The laboratory can extract, store, instantiate and test architectural principles (criteria A–C), but transferred architectural knowledge did not reduce adaptation or search cost in any source→target cell; where it had a measurable effect, it increased cost (§4). The negative v0.1 result is persistent, not noise (§3).

Evidence base: 124 finished experiments, executor(s) ['process'], code at commit(s) `cad9294d4e82`, `d07b0f410b21` (report generated at `cad9294d4e82`). Pre-registered criteria met: **4 of 7**.

## 2. Method summary

- Three synthetic domains: A network anomaly, B scientific verification, C resource-constrained planning (structurally different vocabulary and winners; `docs/domain_planning.md`).
- Identical data, seeds, environment schedule, resource limits, sandbox runner and scoring for every compared agent. Comparisons are paired by seed.
- Target quality per dataset = validation quality of the best-decile point of the enumerated wide architecture space (lab oracle; recorded in provenance). "Evaluations-to-target" = cumulative candidate evaluations when an agent first reached it.
- Memory is per seed; warm conditions read memory written by exploration-mode source runs in the *other* domains. Principles are extracted by deterministic rules, tested only under conditions that did not produce them, and counted by distinct experiments.
- Statistics: mean, median, sd, bootstrap 95% CI, paired delta with CI, Cohen's d on paired differences, sign counts, failure rate, adaptation overhead. Nothing is collapsed into one score.

## 9. Discrimination among the candidate causes of the v0.1 negative result

1. **Insufficient structural memory** — v0.2 memories hold 360 files with 990 principle records ({'UNTESTED': 783, 'INCONCLUSIVE': 191, 'PARTIALLY_SUPPORTED': 16}) plus architecture patterns; retrieval, instantiation and reuse happened in every cell (criterion C). Memory *quantity* is no longer the limiting factor.
2. **Insufficiently different environments** — Domain C has a different component vocabulary, scoring and winners; transfer into and out of it behaved like A↔B (['C->A', 'C->B', 'A->C', 'B->C']). Domain similarity does not explain the result.
3. **Insufficient architecture search space** — the space was widened to ~255 registry points per domain; the evaluation budget covers only a fraction, so candidate ordering by prior knowledge *could* have mattered. It did not reduce evaluations.
4. **Weak architecture representation** — distance analysis (§7) shows final architectures are mostly at zero structural distance from the initial choice in every condition: the IR expresses the space, but the useful region of it is reached by cheapest-first ordering without memory.
5. **Lack of principle abstraction** — principles were abstracted (roles, conditions, effects) and tested; the test outcomes were predominantly contradicted ({'contradicted': 64, 'inconclusive': 10, 'supported': 16}). The abstraction exists; its predictions were mostly wrong under new conditions.
6. **Adaptation economics behaving incorrectly** — criterion E holds; decision and cost-estimate errors are reported in §6. Economics is not what suppressed transfer: the warm agent evaluated *more*, not fewer, candidates.
7. **The hypothesis itself** — with A–C met and D/F/G not met, the remaining explanation consistent with all measurements is that, in these domains, the architectural experience the machine can currently extract does not encode anything that shortens adaptation. Whether this is a property of the rule-based extractor, of the synthetic domains, or of the hypothesis cannot be separated by v0.2 alone; the LLM proposer (Experiment 9) was not run.

## 10. Alternative explanations and limitations

- The domains are synthetic and their useful architectures are cheap; a cheapest-first cold search finds them in 1–3 evaluations, leaving little room for any prior to help. This is a ceiling effect of the benchmark, not evidence for the hypothesis.
- Principle extraction is rule-based with six templates; richer extraction might produce different principles. Tests use the validation slice, which for some datasets has few positives (quantized quality).
- Registry "models" are simulated cost profiles; the 30-seed program used the process executor (identical for all agents); Docker was used for the v0.1 freeze and the example manifests.
- Experiment 9 (LLM proposer) was implemented as a validated pipeline but not executed: no API key on the host and, by design, it comes last.

## 11. Conclusion

**Answer: no.** The laboratory can extract, store, instantiate and test architectural principles (criteria A–C), but transferred architectural knowledge did not reduce adaptation or search cost in any source→target cell; where it had a measurable effect, it increased cost (§4). The negative v0.1 result is persistent, not noise (§3).

What the laboratory established in v0.2: (i) architectural principles can be extracted, stored inspectably, instantiated in a different domain's vocabulary and tested with recorded epistemic outcomes; (ii) the machine records and can be audited on its adaptation economics; (iii) over 13 seeds and a 3×3 transfer matrix, prior architectural knowledge did not reduce the cost of finding a useful architecture in a new domain. The most valuable output of v0.2 is that this negative result is now measured with confidence intervals rather than suspected.
