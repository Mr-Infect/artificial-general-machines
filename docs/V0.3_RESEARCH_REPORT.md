# AGM v0.3 Research Report — verdict: **INCONCLUSIVE**

## 1. Research question

Can AGM recognize that its current computational organization has become inappropriate, infer what kind of organization is now required, decide whether changing itself is worth the cost, construct and evaluate a different architecture, and transfer that structural understanding to an unfamiliar problem without simply reusing a remembered architecture?

## 2. Hypothesis

See `docs/v0.3_design.md` (registered at commit `3853046fcb06`). The hypothesis is falsified if the pre-registered kill criteria fail.

## 3. Experimental design

Per seed: three training runs (network, scientific, planning; training regime library; AGM v0.3 in exploration mode writes one memory file), then six transfer runs (three blind-transfer twins Y, three false-analogy environments Z) under held-out regime combinations with fourteen agents on identical data, budgets (6 candidate evaluations per step), scoring and sandbox. Comparisons are paired by seed. Candidate evaluations use the most recent labelled batch so all agents see the current regime.

## 4. Environment definitions

- telemetry_grid: twin of network (renamed features/components, permuted order, affine-transformed ranges; same hidden structure)


## 5. Regime definitions

Training: calm, turbulent, starved. Held-out: H1, H2, H3 (parameters in `environments/regimes.py`). Three regimes per run in seeded random order with seeded transition steps; constraint changes are observable through telemetry, data regimes are not labelled. Target per regime = top-decile validation quality of a 48-point lab sample of the architecture space under that regime's limits.

## 6. Baselines

fixed, adaptive (role-based presets, degradation-triggered), search (auto space over the available primitives), task_memory (AGM v0.2, same-domain patterns), architecture_memory (AGM v0.2, cross-domain patterns), always_adapt, never_adapt, agm_cold.

## 7. Ablations

agm_full, agm_no_principle, agm_no_archmem, agm_no_negative, agm_no_economics (always adapt with full memory), agm_no_regime.

## 18. Alternative explanations

- Ceiling effects: where the cheapest valid architecture already reaches the regime target, no prior can reduce evaluations-to-useful. The per-environment cold values above show where this holds.
- Role labels are declared by the registry; a twin domain shares them. Blind transfer therefore tests transfer through structural roles and conditions, not through raw component names, but the roles themselves are lab-provided types.
- Rule-based extraction has six positive templates and one negative template; the space of learnable principles is bounded by them.
- Regime detection partly relies on observable constraint changes (memory, cpu, verification cost), which are legitimately observable but easier than inferring data regimes; the no-regime ablation isolates the observation-based part.
- Simulated model costs; process executor for the whole program (identical for all agents).

Which part failed: regime detection, architectural response, economic adaptation, blind structural transfer, negative-transfer avoidance, baseline separation, generalization.
On the transfer question the evidence does not separate AGM from architecture search + memory + heuristics: any adaptation it performs is reproduced by the search baseline and/or by architecture memory alone.
AGM applied prior knowledge where structural conditions made it inappropriate (false-analogy environments), i.e. it did not distinguish useful from misleading analogy.
